# SwiftDrop v0.4.0 — reliability-first milestone

- Streams received payloads in 256 KiB chunks, without buffering the full file in memory.
- Verifies the exact received byte count against both sender metadata and Nearby transport length when known.
- Does not publish MediaStore pending downloads until byte counts match. On failure, removes pending or app-private partial files.
- Interrupts persistence if a local session is cancelled; uses generation checks to reject stale work.
- Clears payload metadata and temporary files when Nearby reports failure or cancellation.
- Limits UI progress state emissions to about 10 Hz, while never suppressing terminal status and continuing to measure actual callback bytes.
- Displays real sender queue position and current-file progress (not fictitious multi-file aggregate percentages).
- Does not introduce a new over-the-wire format; existing Nearby Point-to-Point/QR/permissions remain unchanged.
- Does NOT claim Wi-Fi 7, true pause/resume, end-to-end SHA-256, or measured speed improvements without two-device benchmarks.

## Device QA still required
Send a 0-byte file, normal photo, 2+ GB file, multiple files, identical filenames, and an intentionally interrupted transfer across two Android devices. Verify no truncated file is presented as complete, correct progress/ETA, power-saving behavior, rotation and background behavior. Unit tests and CI alone are not end-to-end transport tests.
